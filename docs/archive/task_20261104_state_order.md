# 状态拖动排序

日期：2026-11-04。

状态行复用页面导航的指针排序机制，新增同页的 before / after 位置与 Alt + ↑ / ↓。状态名称可编辑入口保留，无新增拖拽柄。显示排序独立保存为页面 stateOrder，通过原元数据保存队列和 CAS 提交，状态定义数组不变，避免排序改变默认入口或业务绑定。

orderedStates 供工作台与导出 / 发布导航共用。按保存的 ID 展示已存在状态，新状态按定义顺序追加，旧 ID 不会恢复已删除状态；公开导航白名单携带 stateOrder。原型声明变更继续更新状态配置，不重置手动顺序。

验证：先确认排序函数缺失、公开导航未携带排序、错误排序未拦截的预期失败，再实现。相关排序 / 改名 / 导航 / 扫描 / 导出回归 **42 passed**；扩展到标注、页面导入和元数据后 **235 passed**，报告为 `tmp/state-order-ui/results.xml`。

浏览器使用独立本机测试站，实测第三个状态拖到第一位并自动保存，URL 和当前状态仍为 running，已确认标注保留；跨页面拖动取消；Alt + ↓ 保存；人为在隔离项目创建竞争 revision 后，下一次排序返回 409，列表恢复上次成功顺序。刷新后顺序保留；将非默认状态放首位再点页面，仍进入原 default 状态，切回 running 正常。

效果与结构化验证记录保存在 tmp/state-order-ui，最终独立 / 内联 JS 通过 Node 语法检查，git diff --check 通过。未实际发布 GitHub，未修改真实用户项目。备份与回滚见 docs/backup_log.md。
