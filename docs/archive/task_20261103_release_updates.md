# 发布更新提示与版本说明

日期：2026-11-03。用户确认方案后实施；未向真实 GitHub 提交或发布测试内容。

## 实现

- 新增独立快照 / 事实差异模块，以及本地与静态研发版共用的更新说明 UI。说明只列变化，区分原型、PRD、标注及资源，不自动扩写需求。
- 发布区自动汇总并可编辑说明，绑定源内容指纹、自动保存。上次成功发布作为基线，预览 / 下载 / 发布失败不推进。旧研发包可只读引入基线，本地丢失记录可从公开语义快照恢复。
- 新研发版检查同站静态清单，可见时约 30 秒检查、切回立即检查、失败退避；同内容重发不重复提醒。明显更新条可刷新、查看、稍后收为按钮，支持多版本历史与刷新定位。
- 页面 / 状态 / 标注 / 元素使用结构化目标；复用展开路径和文本编辑语义键。删除内容提供详情，定位失败回退页面，不伪报成功。
- 项目发布使用 Git blobs / tree / commit / 单次非强制 ref，避免半批产物被看到。按内容版本存储原型，保留当前和上一完整资源、最近 10 次轻量说明；只清理已登记发布器文件。
- 旧 AI 发布入口转入同一流程，保留远端身份。使用 Pages 实际分支；不支持的 Actions / docs 源提前明确报错。提交后先标“部署中”，公开站点匹配版本后标记生效。
- 与当前清理、加载过渡和统一发布时间修改共存；未恢复已退役脚本。同步分发副本中遗漏的用户已确认 PRD 背景 / 目标写法。

## 边界与记录

- 新机制需要重新发布研发版；上线前已打开的旧页面首次仍需手动刷新一次。
- 纯净版不注入更新提醒 UI；file:// 不轮询在线站点。
- 静态分析无法可靠推断任意动态代码业务含义，明确列“交互代码有更新，请核对”，不生成虚构业务结论。
- 保留数当前为模块常量 10，无新增配置界面。根目录保留名称冲突会报错，不覆盖用户文件。
- 未使用真实 Token 实测 GitHub 远端发布，原子 Git 流程由隔离内存仓库回归验证；实际 Pages 构建完成时间仍受 GitHub 部署影响。
- 先前清理的 39 个权限受限历史临时目录沿用既有未清理记录，本次未重试改变权限。
