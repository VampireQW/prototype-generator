# 状态名称修改

日期：2026-11-04。

## 实现

- 多状态页面的状态行提供编辑图标及 F2 入口，包含默认状态；单状态页面从页面设置进入同一编辑框。支持空值 / 长度 / 控制字符校验、保存、取消与 Esc。
- 只修改 title，写入 titleUserSet 保护手动名称；状态 ID、类型、页面、PRD、序号、展开和热区配置保留，改名不会切换原型状态。右侧页面需求的范围标题同步使用显示名称。
- 通过现有 protoSave 队列和 expectedRevision 保存，未新增后端接口或元数据版本；声明重新应用时保留手动名称，其他状态配置仍可更新。
- 共用导航在提供 onEditState 的工作台显示改名按钮，纯净 / 研发导航不提供编辑入口。两种导出均读取保存后的状态名称。本地技能导航组件与分发副本同步。
- 弹层跟随重绘后的状态行重新定位，页面加载或状态同步重绘不会清除正在输入的名称；单状态从页面设置切入等待 close 事件，不靠固定延时。

## 验证

先观察缺少改名方法及声明覆盖手动名称的两项预期失败，再实现。隔离接口与导航 / 状态 / 声明 / 导出等相关回归 **36 passed**；扩展至标注和页面导入界面后 **156 passed**，单状态入口与焦点收尾复验 **123 passed**。均使用隔离目录和内存 / 本机测试服务，未调用真实 GitHub 发布。

实际浏览器验证：

- 空名称显示错误，不保存；修改当前状态成功，名称即时更新。
- 非当前默认状态可独立改名，原型仍停留在原 running 状态，已确认标注仍可见且只读。
- Esc 取消不会写入；刷新后两处新名称保留，右侧范围名称正确。
- 单状态页面通过设置修改名称成功，仍不切换当前页面或状态。
- F2 可打开编辑；加载完成触发列表重绘后，已输入的草稿仍保留。

最终 viewer 内联脚本和共用导航通过 Node 语法检查，git diff --check 通过。效果截图：`tmp/state-rename-ui/state-rename.png`。验证只操作新建的虚拟项目，未修改用户示例项目的状态名称或 PRD。

备份和回滚路径见 docs/backup_log.md。需重启本地服务加载声明合并逻辑，并刷新已打开的工作台加载新导航。
