# 2026.10 工作台与 Agent 协作更新

本次更新继续围绕本地 Agent 制作原型、工作台组织页面与 PRD 评审交付，完善多端项目、导航管理和本期需求落库。

## 更新亮点

| 能力 | 本次变化 |
| --- | --- |
| 项目库与工作台 | 采用 Vercel 风格的黑白中性色，统一浅深主题、菜单和弹层；保留真实缩略图，连接状态显示在缩略图上 |
| 多端原型 | 支持 Web、App、Pad 及设备外壳；通过清单区分演示入口和业务页面，工作台、独立入口与研发导出共用导航 |
| 页面管理 | 支持三级页面树、拖拽归类和排序、页面改名、所属端分类、优先级、完成进度及回收站 |
| 项目改名 | 导航顶部显示项目名，修改后同步本地文件夹名称，保持项目身份、PRD 和页面关系 |
| PRD 落库 | 草稿升级至版本 3，背景、目标和标注逐条关联本期需求；按适用内容生成 Markdown，避免补写无关旧功能 |
| 点击提示 | 只提示明确登记的本次交互，容器标注不再使内部所有交互高亮；采用短暂的透明橙色提示 |
| 隐藏标注 | 根据显式展开路径显示入口引导；点击右侧序号自动切换 Tab、打开子视图，等待显示后定位 |
| 发布评审 | 修复内嵌滚动区内序号不跟随的问题；研发导出和 GitHub Pages 共用展开定位逻辑 |

页面回收站支持恢复。彻底删除需在界面中确认文件名，会同步删除指定 HTML 及其关联元数据，保留共享资源。

## 更新与迁移

1. 关闭旧服务，更新源码，保留本机配置和项目目录，然后重新启动原型生成器。
2. 将仓库中的 **`agent-skills/prototype-flow/` 整个目录**更新到使用的 Agent 技能目录，包含 `references/`、`assets/`、`scripts/`。让当前会话重新读取新版入口及对应协议。
3. 多端项目按 [迁移指南](../multi-client.md) 增加清单。演示入口需要显式声明为 `launcher`，不会仅凭文件名或侧栏自动隐藏。
4. PRD 草稿使用 `schemaVersion: 3`，基于最新 revision 重新组织本期需求，不能只修改旧草稿版本号。工作台元数据仍为版本 2，历史 PRD 与人工删除结果不会因更新工具自动改写。
5. 隐藏标注所在的自定义 Tab、弹层或子视图，需要按 [接入约定](../../agent-skills/prototype-flow/references/prototype-contract.md) 声明 `data-proto-reveal-by`。正文写了入口名称，不会自动建立可执行的关联。
6. 已导出或发布的静态评审站需重新导出、发布，才能使用新版序号跟随和自动展开逻辑。

完整 skill 用法见 [Agent 协作指南](../agent-skill.md)。工具校验格式、引用与目标范围；判断内容是否属于本期改造，仍由 Agent 根据用户真实需求完成。

## 发布范围

发布内容包含平台源码、共享导航、完整 Agent skill、文档和隔离测试。个人原型、PRD 数据、本机配置、API Key、GitHub Token、账号数据、上传文件、缓存、备份和调试记录不进入源码提交。

逐项变更见 [更新日志](../changelog.md)。
