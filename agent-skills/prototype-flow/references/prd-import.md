# PRD 草稿与落库

## 先读事实，再分类

读取本次已确认的需求、项目 `.prototype/brief.md`、相关 HTML，以及已登记的 `.prototype/project.json`。列出目标文件内实际存在的 `data-proto-id`，不能给不存在的元素编造标注。

| 内容 | 放在哪里 |
| --- | --- |
| 页面用途、使用对象、整体流程、公共业务规则、已确认的数据来源与异常处理 | 页面需求文档 `document` |
| 某个控件的点击去向、校验、禁用条件、格式或空值表现 | 绑定该元素的 `annotations` |

标注简短、具体，不重复整页说明；页面文档可用 `## 一、需求描述` 和 `## 二、研发实现` 组织。多状态页面按每个已实现、已登记的状态分别整理文档与标注，不把所有 Tab 的需求堆到 `default`。

只写原型实际体现或用户明确确认的内容。示例人物和数值不是业务规则；接口、权限、阈值等没有依据时放进 `unknowns`。它们只在导入报告中回显，不会保存为工作台需求；保留在草稿 / brief 中并向用户提出，不能声称已自动补全。

## 草稿格式

写入原型项目 `.prototype/prd.draft.json`，UTF-8，合法 JSON：

```json
{
  "schemaVersion": 1,
  "pages": [
    {
      "file": "index.html",
      "stateId": "default",
      "document": "## 一、需求描述\n当前页面展示列表与新建入口。\n\n## 二、研发实现\n按原型中已实现的状态切换；真实数据来源待确认。",
      "annotations": [
        {
          "protoId": "btn-create",
          "body": "点击进入原型已实现的新建视图。"
        }
      ]
    }
  ],
  "unknowns": ["真实数据来源是什么（需求未提供）"]
}
```

这是格式示例，替换为真实页面和已确认的交互。`file` 为项目相对路径，也可用登记后的 `pageId`；同时提供时 `file` 优先。`stateId` 省略为 `default`，必须已登记；`document`、`annotations` 可分别省略。草稿 schemaVersion 为 1，工作台保存的元数据 schemaVersion 为 2，两者不要混用。

## 执行导入

从任意工作目录调用工具仓库中的脚本，优先传原型项目根目录：

```text
python "<工具仓库>/proto_import.py" "<原型项目>" --dry-run
python "<工具仓库>/proto_import.py" "<原型项目>"
```

首次检查无阻碍后完成正式导入，不把 dry-run 当成已落库。默认草稿路径为 `<原型项目>/.prototype/prd.draft.json`，也可显式传入第三个参数。已登记项目可以用 `p-` 加 16 位十六进制字符的项目 ID 替代根目录，ID 从该工具实例的本地登记信息获取，不编造 ID。

| 选项 | 实际行为 |
| --- | --- |
| `--dry-run` | 不保存 PRD 文档和标注、不归档草稿；仍会建立元数据或补登记新 HTML 页面，并非完全只读 |
| `--skip-missing` | 跳过不存在 / 不唯一的 protoId 并报告；只在用户接受部分导入时使用 |
| `--replace-doc` | 覆盖已有正文但尚未确认的页面文档；仅在本次任务明确要求更新正文时使用，已确认文档仍不覆盖 |

脚本对每个文件中的 protoId 做唯一性校验。默认任一目标缺失 / 重复则不写入本次 PRD 内容；页面登记可能已发生。同页同状态已有同 protoId 的标注会跳过，不会更新它的正文。已有非空页面正文默认保留，`confirmed: true` 的内容保留。

有实际文档 / 标注变更时，脚本生成锚点与序号、校验元数据、增加 revision，并将草稿移入 `.prototype/imported/`。无变更的重复导入不会增加 revision 或归档草稿。不要自己重复生成 anchor、placement 或手动修改三文件。

## 回报与异常

- 核对脚本报告中的文档 / 标注数、revision、跳过项、隐藏目标提醒和 unknowns；正式导入后可用 `proto_meta.load_bundle` 读取验证。
- 项目未加入首页时，按接入约定添加本地项目；已打开的工作台刷新后查看。
- 非 0 退出时说明具体错误并保留草稿，修正有依据的草稿内容；不要把失败说成成功，不通过删标注、改确认状态或给错误元素塞 ID 来绕过校验。
- 元数据冲突或保存中断时停止保存并报告，不用旧快照覆盖新数据，也不删除 `.pending-write.json`。
